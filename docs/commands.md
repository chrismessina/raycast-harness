# `rx` command contracts

This file is written before the code. Every command here has an **argument schema**, a **root rule**, a **`data` schema**, a **state location** and a **network boundary**; `rx <command> --help` and `rx commands --json` report the same facts from the code. If the code and this file disagree, the code is wrong.

Plan references (`§4.x`) point at `docs/plans/2026-10-30-raycast-harness.md` in the `chrismessina/raycast-extensions-skills` repository.

## 1. Shared protocol

### Verdicts

One line per check: `VERDICT  check-id  message`. `VERDICT` is one of `PASS`, `FAIL`, `WARN`, `N/A`, `ERROR`. A check id is kebab-case. `N/A` always states why there was nothing to inspect. Silence is never a pass: a command that produces no result at all is an `ERROR protocol`.

| Exit | Meaning |
|---|---|
| 0 | only `PASS`, `WARN`, `N/A` |
| 1 | at least one `FAIL` |
| 2 | at least one `ERROR` (outranks `FAIL`) |

One command speaks a different protocol without `--json`: `rx guard`, the Claude Code hook, prints nothing on allow and one JSON decision document on block, exit 0 either way (§4.9 "Transport"); with `--json` it is an ordinary command.

`ERROR` is for a check that could not run: unknown or malformed arguments (`ERROR args`), an unresolvable root (`ERROR root`), unreadable or malformed input (`ERROR input` or a command-specific id), a tool missing from PATH (`ERROR tooling`), a network failure inside the command's purpose (`ERROR github`, `ERROR npm`). A check that ran and found a problem is a `FAIL`.

Domain outcomes (`SAME-PIXELS`, `OURS-SAFE`, `MINE`, `CHECK`, …) are **never extra verdicts**: they are values inside `data` or inside a result's `details`, and each command below gives its mapping to `PASS`/`FAIL`/`WARN`/`N/A`.

### `--json`

Every command accepts `--json` and then prints exactly one document:

```json
{
  "command": "preflight",
  "version": "0.1.0",
  "fingerprint": null,
  "data": { },
  "results": [
    { "id": "readme-assets", "verdict": "FAIL", "message": "1 image path does not resolve",
      "details": [ { "file": "README.md", "line": 12, "text": "metadata/missing.png" } ] }
  ],
  "exit": 1
}
```

`fingerprint` is a string only for commands that compute one (`gates`, `guard`, `audit`); otherwise `null`. `details[]` entries have `text` and optionally `file` (repo-relative or extension-relative, as the command documents) and `line` (1-based).

### `--help`

Every command and subcommand accepts `--help` and prints its usage, arguments, flags, root rule, network boundary and state location as text, exit 0. `--help` waives only the missing-required-input checks: every other token is still validated, so `rx preflight --help --bogus` is `ERROR args`. `--help` and `--version` cannot be combined with `--json` (`ERROR args`); every other invocation with `--json` prints exactly one document.

### Arguments

Flags are `--name value` or `--name=value`; booleans take no value. **Any unknown argument, a flag without a value, an empty value, any flag given twice (booleans and `--json` included, unless declared repeatable), a missing required argument, an unknown or missing subcommand → `ERROR args`, exit 2.** A command module may export `invalidate({ root, subcommand, cwd })`; on `ERROR args` the dispatcher calls it with what the parser itself had established before it threw (the subcommand it selected, null when none or unknown; the flags parsed so far): the root resolves from cwd when no `--root` token was given, from the parsed `--root` value when exactly one was given and parsed, and is null otherwise (an empty, missing or never-parsed value, or two `--root` tokens: an explicit root that cannot be read names no repository, and the cwd's is never the fallback). So a command that deletes a prior authorization at the start of its run (`gates`, `audit record`) deletes it on a parse error too. It is best-effort, its own failure is never reported, and `--help` with `--json` (an `ERROR args` that is a help request) never invalidates. Positional arguments are declared per command. There are no short flags. For a command with subcommands, the subcommand is the first token that is neither a flag nor the value of a valued flag (`rx audit --root d show` selects `show`). A command either has subcommands or positionals, never both at the top level.

### Root resolution (every command whose root rule is `required` or `optional`)

1. `--root <dir>` wins. It must be an existing directory; otherwise `ERROR root`.
2. Otherwise walk up from the current directory to the nearest `package.json` whose parsed content has a `commands` array.
3. If none, look one level down: the immediate subdirectories (not `node_modules`, not dot-directories) that satisfy the same test.
4. Exactly one candidate → that is the root. **More than one → `ERROR root` naming them and asking for `--root`.** None → `ERROR root` asking for `--root`, except for `optional`-root commands, which then run with no root and report the dependent checks as `N/A`.

The dispatcher resolves the root before the command runs; a command never sees an ambiguous root.

### State locations

| Kind | Where | Holds |
|---|---|---|
| repo state | `git rev-parse --git-path rx` in the extension's repository (so `.git/rx/` in an ordinary checkout, the worktree's private dir in a worktree) | `receipt.json` (with `inputs` and `data.stale`), `audit.json`, `stale/baseline.json`, `greptile/<repo>/<N>/` (rounds, etag, replies; when a root resolves), `holdout/`, `publication.json` |
| cross-repo cache | `$XDG_CACHE_HOME/raycast-harness`, default `~/.cache/raycast-harness` | the sparse `raycast/extensions` checkout (`upstream/`) and its per-extension record `upstream-meta/<name>.json` `{ name, published, publishedDir, baseline, at }` (lets `gates` reuse a fresh fetch), the runtime shortcut table (`shortcuts/<fingerprint>.json`), PR body backups (`pr-body/<repo>/<N>/`), Greptile rounds when no root resolves (`greptile/<repo>/<N>/`) |

This table is the canonical state map; a command section may only repeat it. Nothing is written into the extension's payload (the files `ray publish` copies) or into the npm installation of `rx`, with exactly these documented exceptions: `rx changelog --merge` rewrites `CHANGELOG.md` in the root; `rx holdout out` moves untracked local-only files out of the root and `in` moves them back; `rx greptile drift --update` writes into the explicit `--dest` checkout; `rx preset table --into <file>` rewrites the generated region of that one explicit file (a plugin reference file; it refuses a destination under an extension root that resolves from the file's directory).

### Network

Each command states its boundary. Unless the boundary says so, a command opens no connection and starts no child process that does. `git`, `gh`, `npm`, `npx`, `ray`, `plutil` run through `execFile` with argument arrays; `ls`, `grep`, `find`, `sed` are never run. `rx` runs plain `gh`; only when `gh` reports it is not authenticated and `op` (1Password CLI) is on PATH does it retry through `op plugin run -- gh`, because on some machines `gh` is a shell alias for that wrapper and an alias does not exist inside `execFile`.

Two documented exceptions to "network failure is `ERROR`": `guard` speaks the host hook's allow/block transport; `api-floor`'s npm-currency advisory reports `N/A (npm unreachable)` while its local floor check still runs.

### Presets

Commands marked **preset-aware** accept `--preset <file>`, a JSON file validated against `schema/preset.schema.json` (§4.16). Core without a preset enforces only ecosystem facts; preset-class checks are then `N/A (no preset)`. A preset binding may set the severity of a core check only for the house-style rule it binds and can never downgrade an unrelated core `FAIL`. The plugin runner always passes `--preset`.

## 2. Commands

Legend: **Root** `required` / `optional` / `none`. **Network** as stated. **State** read/written. **Verdict mapping** lists check ids the command emits; `N/A` reasons are literal.

### `rx commands [--json]`

Lists every command's contract. **Root** none. **Network** none. **State** none.
**data** `{ commands: [{ name, summary, root, network, state, positionals[], flags{}, subcommands{}, checks{}, data{} }] }` — `flags` includes the global `--json` and `--help`; `subcommands` entries have the same shape; `checks` maps every check id the command may emit to a one-line description or to `{ description, levels }` where `levels` lists the verdicts the check can produce (absent = assumed able to FAIL), a key ending in `*` declaring a prefix (`"stale-*"`). This is the registry `rx preset check` validates `rx` bindings against: a binding's `check` must equal a key or match a declared prefix.
**Verdicts** `PASS commands <n> commands: …`.

### `rx doctor [--root <dir>] [--json]`   (§4.15)

Report only: never `FAIL`. **Root** optional. **Network** `gh auth status` contacts github.com; all else local. **State** none.
**data** `{ node, ray: { found, apiVersion } | null, gh: { authenticated, login, detail }, signing: { gpgsign, format, key }, raycastApp: { version, path, installed, error } }`.
**Verdicts** `node` (PASS ≥ 22.12 / WARN), `ray` (PASS present / WARN missing / `N/A no extension root resolved`), `gh-auth` (PASS / WARN), `git-signing` (PASS / WARN; `commit.gpgsign` read as a git boolean), `raycast-app` (PASS / WARN `installed but its version could not be read` / `N/A Raycast.app not found` / `N/A not macOS`).

### `rx preflight [--root <dir>] [--published <dir>] [--preset <file>] [--json]`   (§4.1, §4.16, §11.1)

The Store-readiness checks, formerly `scripts/preflight.mjs`. **Root** required. **Network** none. **State** none (read-only). Preset-aware.
`--published <dir>` is the extension as it exists in `raycast/extensions` (what `rx stale` fetches); it enables the comparison checks. Without it they report `N/A (not published; pass --published)`.
**Check classes** are recorded in `docs/check-classes.md`: every legacy id is `core` or `preset`; preset-class checks take values, applicability and severity from the preset and are `N/A (no preset)` without one.
**Check ids** — legacy (27): `schema`, `categories`, `platforms`, `preference-type`, `hand-typed-preferences`, `title-case`, `shortcut-platform-case`, `changelog-exists`, `changelog-order`, `changelog-updated`, `command-renamed`, `eslint-config`, `prettierrc`, `lockfile`, `npm-registry`, `native-fetch`, `unused-dependencies`, `readme-assets`, `screenshots`, `package-json`, `agent-scaffolding`, `dev-material`, `generated-files`, `launch-command`, `favicon`, `trash`, `localization`. New (§4.1): `screenshot-count` (≤ 6), `screenshot-format` (`.png` only; anything else under `metadata/` is FAIL), `screenshot-size` (2000×1250), `icon-size` (512×512), `readme-links` (every relative link in README and docs resolves from its own directory, any Markdown form; `readme-assets` judges embedded images only, never a plain link to an asset; both exclude fenced, inline and 4-space-indented code, extract `srcset` candidates and multi-line destinations, and honor balanced parentheses in destinations), `changelog-placeholder` (zero placeholders FAIL; the top entry must carry `{PR_MERGE_DATE}`), preset-bound: `pref-description-length` (≤ 80, report), `pref-label-length` (< 50, report), `logger`, `logger-verbose-copy`, `logger-strict-redaction` (report-only), `agents-md-paths`, `agents-md-scripts`, `agents-md-no-home-paths`, `agents-md-symbols` (§11.1, self-authored only). Every id is emitted on every run as PASS/FAIL/WARN/N/A. **Absence rule:** a check whose subject is a *required* artifact FAILs when it is missing (`package-json`, `schema`, `categories`, `changelog-exists`, `lockfile`, `eslint-config`, `readme-assets` when README.md is missing, `icon-size`, and `prettierrc` under a preset); a check whose subject is *optional* reports `N/A <subject> absent` (`screenshot-count`, `screenshot-format`, `screenshot-size` with no `metadata/`; `screenshots` itself keeps the legacy rule: a `view` command with no screenshots is a FAIL, `preference-*` with no preferences, `logger*` with no logger, `agents-md-*` with no AGENTS.md or CONCEPTS.md, `shortcut-platform-case` with no shortcuts, the four heuristics with no source hits are PASS). `package-json` FAILs for any manifest that is not a JSON object (`null`, an array, malformed). When several applicable preset rules bind the same check with different `options`, every binding is evaluated and the strictest outcome stands. `changelog-placeholder` has one normative predicate shared with `rx changelog` (one implementation, `src/changelog/parse.mjs`, imported by preflight): exactly one `{PR_MERGE_DATE}`, and it is on the top entry's heading; zero, more than one, or one on a non-top entry → FAIL; `changelog-order` is the legacy descending-dates check.
**data** `{ root, published: boolean, publishedDir: string | null, preset: string | null, selfAuthored: boolean | null, checks: { [id]: "core" | "preset" } }`.
**details** `file` is extension-relative; `line` where the finding is in a file.

### `rx stale [--root <dir>] [--json]`   (§4.2)

Is the published copy of this extension older or different from what is here? **Root** required (resolved before any lookup; fixes Q3). **Network** GitHub API (`gh api repos/raycast/extensions/contents/extensions/<name>` to detect publication and the baseline SHA) and `git fetch` of `raycast/extensions` into the cross-repo cache. **State** reads/writes `cache/upstream/` (sparse checkout, persisted for `gates`, `preflight --published`, `png`, `contributions`); writes `repo/stale/baseline.json` `{ name, baseline, publishedDir, published, at }` (`rx api-floor` reads `published`).
Any lookup failure other than 404 → `ERROR github`. 404 → `data.published: false`, `publishedDir: null`, `baseline: null`, one result `N/A stale not published`.
Both sides are compared minus **only** `ray`'s copy skip list (`src/payload.mjs`): everything the publisher copies is classified, including `.prettierrc*`, `.eslintrc*`, `dist/` and `.DS_Store` (`.direnv` is on the publisher's skip list; the legacy recipe's `grep -v` of those is exactly what Q18 retires; a differing `.prettierrc` is a real difference). Uncommitted executable-bit changes count: the working file's mode is compared with the published mode before identical content is accepted. `localHash` in `data.files[]` is the git blob id of the on-disk bytes (`null` when absent locally); MINE / CHECK / UPSTREAM compare committed blob ids.
**Classifier** per path (symlinks and mode changes included): `MINE` published == local HEAD blob; `CHECK` published == an older commit of this path; `NEW?` local file the published tree lacks; `UPSTREAM` published blob not in this path's history; `ONLY-PUB` published has a file local does not; `UNHANDLED` symlink, mode change, or an undecidable line.
**Verdict mapping** one result per class actually present, id `stale-<class>` (`stale-mine`, `stale-check`, `stale-new`, `stale-upstream`, `stale-only-pub`, `stale-unhandled`), details one per path: `MINE` → PASS; `CHECK`, `NEW?` → WARN **requiring an audit disposition** (`rx audit record`, keyed by path + local content hash + baseline SHA) before `guard` allows publishing; `UPSTREAM`, `ONLY-PUB`, `UNHANDLED` → FAIL. A fully identical tree → `PASS stale-mine identical to published`. Readers hold the upstream cache lock for the whole comparison so a concurrent fetch for another extension cannot swap the tree under them.
**data** `{ name, published, publishedDir, baseline, files: [{ path, class, localHash, publishedHash | null, note }] }`.

### `rx png [--published <dir>] [--root <dir>] [--json]`   (§4.3)

Read-only screenshot/icon triage: recommends, never modifies. **Root** required. **Network** none. **State** none; a `--published` directory inside the upstream cache is read under the cache's reader lock (`src/upstream.mjs` `withUpstreamLock`), as `preflight --published` does. Decodes with `pngjs`; reads IHDR bit depth and the `gAMA`, `iCCP`, `sRGB`, `cHRM` chunks with a bounds-checked chunk reader. Compares every `.png` under `metadata/` and the icon(s) named in `package.json` with the same path under `--published`.
**Outcomes → verdicts**, one result per file, id `png`, outcome in `details[0].text` and `data.files[].outcome`: `SAME-PIXELS` (equal size, RGBA and color metadata) → PASS, recommend adopting the published copy; `UNDECIDED` (bit depth > 8 or metadata differs) → FAIL, compare by eye; `LOCAL-ONLY` (no published copy, or no `--published`) → `N/A keep local`; `OLDER-SHOT` (differs; the **published** image is pixel- and color-metadata-equal to an older commit of this path, so the Store holds an older shot of yours) → WARN requiring an audit disposition (path + local hash + baseline SHA; historical membership alone never authorizes keeping local); `NOT-YOURS` (differs; the published image matches nothing in this path's history: a contributor's or a restored image) → FAIL. Both files are fully decoded before any outcome is chosen; a decode or chunk failure → `ERROR png` for that file (`data.files[].outcome: "ERROR"`), never LOCAL-ONLY or DIFFERENT; decoding inflates the IDAT stream and checks its length against IHDR itself, because `pngjs` silently zero-fills a damaged image; pixels differ but the root is not a git work tree (provenance cannot run), or `--published` is not a directory → `ERROR png`; no PNG under `metadata/` and no icon → one `N/A png` with the reason.
**data** `{ published: boolean, files: [{ path, outcome, local: { width, height, bitDepth, colorType, gAMA, iCCP, sRGB, cHRM }, published: {…} | null, provenance: string | null (the commit whose blob the published bytes match, for OLDER-SHOT), localHash: "sha256:…", baseline: string | null }] }`.

### `rx scan --forbidden <file> [--pr-text <file>]... [--root <dir>] [--json]`   (§4.4)

Gate −2: do any forbidden example values leak? **Root** required. **Network** none (reads git history locally). **State** none.
`--forbidden` is a text file, one literal per line (blank lines and `#` comments ignored). Scans: file **contents and names** of the payload (extension root minus `ray publish`'s fixed skip list, ignored and untracked included; `src/payload.mjs`; a file symlink is scanned through to its target's bytes, as `ray`'s copy follows it, and an unreadable target is `ERROR scan-files`), the full commit messages (`%B`) in the range `ray` itself logs: `HEAD...<publish-tag>` where the tag is `__raycast_latest_publish_ext/<package name>__`, the publisher's form built from its `ext/<name>` branch (`src/publish-tag.mjs`; a bare `__raycast_latest_publish__` left by an older publisher is NOT a boundary, because the publisher itself reads only the `ext/<name>` tag and logs all history without it; this equals `<tag>..HEAD` when the tag is an ancestor; `ray` logs only `%s`, so scanning `%B` is stricter), else all history; and every `--pr-text` file. `data.range` is the literal `git log` argument (`"HEAD...<tag>"` or `"HEAD"`), `null` outside a git work tree.
**Verdicts** `scan-files`, `scan-names`, `scan-commits`, `scan-pr-text` (each PASS / FAIL with one detail per hit; a file hit is `{ file, line, text }`, a commit hit is `{ file: "commit:<sha7>", line, text }`, `text` being the forbidden line matched; `scan-pr-text` is `N/A no --pr-text given` when absent); `scan-binary` WARN listing binary files for a human look (PASS when none). Empty forbidden file → every check `N/A every example approved (forbidden list is empty)`, never PASS.
**data** `{ forbiddenHash: "sha256:…", forbiddenCount, range: string, hits: number, binaries: string[] }`.

### `rx changelog [--root <dir>] [--published <dir>] [--redactions <file>] [--merge] [--json]`   (§4.5)

**Root** required. **Network** none. **State** `--merge` reads `MERGE_HEAD` and writes `CHANGELOG.md` in the root; otherwise read-only.
**Verdicts** `changelog-placeholder` (exactly one `{PR_MERGE_DATE}`, in the top entry; zero or misplaced → FAIL), `changelog-history` (dated entries byte-equal to `--published`'s **except recorded redactions**; `N/A (not published; pass --published)` without it), `changelog-bullets` (each ≤ 280 chars; WARN), `changelog-merge` (only with `--merge`: rebuilt from HEAD and MERGE_HEAD by heading structure → PASS; ambiguous boundary → `ERROR changelog-merge` with the two headings in details, nothing written).
`--redactions <file>` is JSON `[{ heading, originalHash, replacementHash, forbiddenLine }]`; an entry authorizes exactly one changed body whose published text hashes to `originalHash` and local text to `replacementHash`, dates unchanged. Hashes are `sha256:<hex>` over the entry body's exact bytes (the lines under its `## ` heading up to the next `## ` heading, internal line endings preserved) with leading and trailing blank lines removed; no newline normalization anywhere in the history or containment comparisons. `--merge` reads and validates every input (`--published` included) before it writes anything. A working file holding `<<<<<<<` conflict markers without `--merge` → `changelog-placeholder` FAIL `conflict markers present`; `--merge` without `MERGE_HEAD` → `ERROR changelog-merge`. A stamped heading and its `{PR_MERGE_DATE}` form are the same entry.
**data** `{ placeholders: number, topHeading, entries: [{ heading, date, bullets, changed, redacted }], merged: boolean }`.

### `rx contributions --published <dir> [--root <dir>] [--json]`   (§4.6)

Run during a `pull-contributions` merge, from the extension root or a monorepo checkout. **Root** required. **Network** none. **State** none.
For each conflicted path under the extension subtree compares the **incoming** (theirs, `MERGE_HEAD`) blob with the **published** blob for that path. The decision uses only those two: `OURS-SAFE` means *incoming == published*, so taking ours discards nothing the contributor wrote; `REAL-CONTRIBUTION` means *incoming != published*. The local (ours) blob never enters the decision: with ours == published and incoming != published, the result is `REAL-CONTRIBUTION`. Path sets compared in both directions; a missing object → `ERROR contributions`. CHANGELOG containment decides only `CHANGELOG.md`.
**Verdicts** one result per conflicted path, id `contribution`, details `{ file, text }` with `text` one of `"OURS-SAFE incoming <blob> == published <blob>"`, `"OURS-SAFE incoming <blob> is contained in ours <blob> (every incoming CHANGELOG entry is already here, byte for byte)"` (CHANGELOG.md only), `"REAL-CONTRIBUTION incoming <blob> != published <blob>"`, `"REAL-CONTRIBUTION incoming <blob>; published copy lacks <path>"`: `OURS-SAFE` → PASS, `REAL-CONTRIBUTION` → FAIL. No `MERGE_HEAD`, or a `--published` directory that does not exist or is empty → `ERROR contributions` (declared in `spec.checks`); the flag itself missing is the shared `ERROR args`. Path sets are compared over the whole subtree minus only `ray`'s skip list (no compare-noise filter). CHANGELOG containment treats a stamped heading and its `{PR_MERGE_DATE}` form as the same entry and compares bodies byte for byte (line endings included). `contribution-branch` WARN when a merged PR's leftover `ext/<name>` branch exists whose only new commit is raycastbot's date stamp, else PASS. No conflicts → `N/A no conflicted paths under <extension>`.
**data** `{ extension (the subtree relative to the repository top level; "" for a standalone checkout), conflicted: [{ path, outcome, ours, incoming, published }], incomingTree: { onlyIncoming, onlyPublished, differing } (MERGE_HEAD's extension subtree vs --published, both directions), leftoverBranch: { name, commit } | null }`. `contribution-branch` is network-free: it inspects local refs (`refs/heads/ext/<name>`, `refs/remotes/*/ext/<name>`) and `MERGE_HEAD` for a lone raycastbot date-stamp commit.

### `rx api-floor --preset <file> [--root <dir>] [--json]`   (§4.7)

Dependency policy comes **only from the preset** (`dependencies.api`). **Root** required. **Network** optional npm registry read for the currency advisory. **State** none.
Policy selection, in this order: (1) no lockfile → `ERROR api-floor-lockfile`; (2) lockfile-resolved `@raycast/api` major 1 → policy `existing-1x`, major 2 → `2x`, anything else → `ERROR api-floor-lockfile`; (3) publication status comes only from `repo/stale/baseline.json` written by `rx stale`: `published: false` → the extension is new; `published: true` → existing; file missing, unparsable, or without a boolean `published` → unknown (and `ERROR api-floor-baseline` is NOT raised: an unknown status is a reason to run `rx stale`, which `rx gates` does first).
**Verdicts** `api-floor-lockfile` (resolved ≥ the selected policy's floor → PASS, else FAIL), `api-floor-manifest` (the manifest range's lower bound ≥ floor → PASS, else WARN; no range → WARN), `api-floor-new` (new and major 1 → FAIL `new extensions start on 2.x`; new and major 2 → PASS; existing → `N/A published extension`; unknown → `N/A run rx stale first to learn whether the extension is published`), `api-currency` (resolved == npm latest → PASS; behind → WARN; npm unreachable → `N/A npm unreachable`). There is no `--new` flag. Without `--preset`: `ERROR args`.
**data** `{ policy, floor, resolved, range, latest: string | null, publication: "new" | "existing" | "unknown" }`.

### `rx gates --preset <file> --forbidden <file> [--root <dir>] [--json]`   (§4.8)

Runs the mechanical gates in order and writes the receipt. Run `rx holdout out` first when the tree holds local-only files: they are inside the payload fingerprint, so moving them after `gates` stales the receipt (§4.11). **Root** required. **Network** `stale`'s (GitHub, git fetch) and `api-floor`'s optional `npm view` currency lookup; `npm run build` and `npm run lint` do what the project's scripts do; never installs packages (missing local tooling → `ERROR tooling`). **State** deletes then writes `repo/receipt.json`; reads `repo/stale/`; uses the cross-repo `upstream/` cache.
Order: `stale` → `scan` → `preflight` (with `--published <stale's dir>` when published, without it otherwise) → `api-floor` → `npm run build` → `npx --no-install tsc --noEmit` → `npm run lint`. Each step's results are merged into the output with their own ids; the three tool steps are `build`, `tsc`, `lint` (PASS / FAIL with the tool's first error lines in details).
**Fingerprint** (`src/fingerprint.mjs`, no git writes): `fingerprints.payload` = SHA-256 over a sorted, length-delimited manifest of every path in the publisher copy set (ignored and untracked included): path, entry type, executable bit, symlink target, bytes. Plus `head`, `publishRange`, `preset`, `forbidden`, `rxVersion`, `baseline` (the published baseline SHA or the literal `unpublished`). `data.fingerprints.combined` and the envelope `fingerprint` carry the combined SHA-256 of all of them. The payload fingerprint is taken before the first step and again after the last; a difference (a build or lint autofix that changed a shipped file) is `FAIL gates-tree-changed` and no receipt is written, because the earlier steps never inspected the final tree. The compared fields are payload, HEAD, publish range, preset and forbidden. The receipt is deleted immediately after the state path resolves, before `--preset`/`--forbidden` are validated, so a bad invocation never leaves a stale authorization. A symlink's manifest entry carries the dereferenced target's executable bit beside the link's own mode. `baseline` is the literal `unknown` when `rx stale` has not recorded a baseline; `publishRange` includes the publish tag's commit (`HEAD...<tag>@<sha>`) so a moved tag changes it; `preset` and `forbidden` are the literal `missing` when the file cannot be read.
**Receipt** `repo/receipt.json` `{ fingerprints: {…}, inputs: { preset, forbidden }, results: Result[], steps: string[], data: { stale }, rxVersion, at }`: `inputs` holds the absolute paths whose bytes were fingerprinted, so `rx guard`, which takes no flags, can re-hash them; `data.stale` is `stale`'s data (the CHECK / NEW? rows `rx audit record` matches dispositions against). Written **only when no step produced FAIL or ERROR**, to a temp file in the state dir and then renamed. An interrupted run leaves no receipt. The previous receipt is deleted as the first action of a run, before any input is validated, and also when the arguments fail to parse (the dispatcher calls the module's `invalidate` export, §1; an explicit `--root` that cannot be read deletes nothing, and `--help --json` never invalidates), so a run that ERRORs on its arguments never leaves an old authorization behind.
**data** `{ receipt: string | null, fingerprints, steps: [{ name, exit }] }`.

### `rx guard [--json]`   (§4.9)

The plugin's `PreToolUse` hook. **Root** `none` for the dispatcher; the command itself calls `resolveRoot({ cwd: payload.cwd })` with the hook payload's `cwd` after reading stdin (a failure to resolve blocks with that reason). **Network** none. **State** reads `repo/receipt.json`, `repo/audit.json`.
Reads the hook payload (JSON) on stdin. The Bash command is read against an **exact-shape allowlist** (`src/audit/publish-command.mjs`), not a shell parser. A **publish** is the whole command being `npm run publish` or `ray publish`, optionally preceded by exactly one `cd <literal dir> &&` and followed by plain output redirections (`> f`, `>> f`, `2> f`, `2>&1`, `&> f`) with literal targets; no options, no quotes around the words, no `npx`, no wrappers, no variables, no second command, no newline. The `cd` target must say where it points without the shell: absolute (`/…`), explicitly relative (`./…`, `../…`, `.`, `..`, with or without a trailing slash) or `~`/`~/…`; the absolute and explicitly relative forms may also be quoted whole with nothing expandable inside (`"."`, `"../other/"`); a bare name (`cd src`, which CDPATH could redirect), `~user`, `~-`, `~+`, a quoted `"~"` (literal in bash), a word starting with `-`, and any `$`, backtick or glob are refused. The publish is checked against the extension that resolves from that directory (resolved against the payload's `cwd`; `~` is the home directory) or from the `cwd` itself. A command whose text mentions the word `publish` (whole word, after backslash-newline continuations are joined and quotes and backslashes stripped) without being one of those shapes blocks with "cannot determine what this command runs: the guard allows a publish only as the whole command `npm run publish` or `ray publish` …" — so `npm run "publish"`, `npx ray publish`, `FOO=1 npm run publish`, `npm publish`, `npm run publish; npm test` and `git commit -m "ray publish"` all block, and the agent rewords or splits the command. Words that merely contain `publish` (`--published`, `publishRange`, `--record-publication`, `publishing`) are not mentions. A command whose text mentions marking a PR ready (`pr ready`, `draft=false`, `ready_for_review=` with an assignment, `markPullRequestReadyForReview`, same normalization) always blocks ("marking ready is Chris's click"), whatever else it does; the ship skill's attribution query, which reads timeline events named `ready_for_review`, is a read and passes. The `cd` target is resolved physically (`realpath`) before the root is looked up, so a symlink into another extension is checked against that extension; a target that does not exist blocks. Any other command → allow, without reading any state. A publish is allowed only if (a) the receipt exists and is well-formed (`inputs`, non-empty `results` with at least one result per step, `data.stale`, `rxVersion` equal to the running version), (b) every fingerprint equals a fresh computation, (c) every required step is present with no FAIL/ERROR, and (d) `audit.json` exists, is well-formed, carries the same combined fingerprint, and its decision, recomputed from the stored entries, dispositions, verifications and evidence with `src/audit/evaluate.mjs` and with its `applicable` and `required` lists cross-checked against live applicability, the receipt's stale rows and the embedded png evidence, has no blocking reason. Receipt presence, step names or a stored `blocking: []` alone never authorize. Otherwise block with one sentence naming what is missing or stale.

**Threat model and two documented limitations.** The guard is a seatbelt for an agent following the ship skill, not a sandbox. (1) A command that builds the word `publish` or `ready` at run time (`"$(printf pub)lish"`, `$X`, `eval` over a file) is not a mention and passes; `rx-calls-check` keeps the plugin's own rx calls canonical, and the ship skill requirement below covers the publish itself. (2) The receipt and audit are files under `.git/rx/` that the same agent could write by hand; the validation in (a)–(d) proves shape and consistency with the tree, not that `rx gates` ran. A provenance mechanism (an attestation keyed outside the agent's reach) is an open item for a later version, not v0.1. Both limitations put two requirements on the rewritten `ship` skill (Phase 5; the current skill predates rx and states neither): it must spell the publish exactly as the allowlist admits and never construct the words, and it must never write under `.git/rx/`. The hook is inert until Phase 9 activates the plugin (D8).
**Transport** (the documented exception): on allow, prints nothing and exits 0; on block, prints the hook's JSON decision document on stdout and exits per Claude Code's hook contract, which the implementer records from the current docs in the hook's source header. Without `--json` the command returns `transport: { stdout, exit }` and the dispatcher writes it verbatim: allow → empty stdout, exit 0; block → `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"<sentence>"}}`, exit 0 (https://code.claude.com/docs/en/hooks). A protocol error (an undeclared check id) outranks the transport and prints as `ERROR protocol`, exit 2, which the hook contract also reads as a block. `gh pr ready` detection also covers `gh api … draft=false` and the GraphQL `markPullRequestReadyForReview` mutation. A publish from a cwd where no root resolves blocks with that reason. `--json` instead prints the envelope with `guard` as PASS (allow) / FAIL (block) / `N/A not a publish or ready command` and exits per the verdict, for tests. `data` is `{ decision, reason, command, roots, receipt, audit }`: `roots` holds the one physical root checked, or is empty; `receipt` and `audit` are the `{ present, fresh, complete }` / `{ present, fresh, blocking }` states of that root and are `null` on every return before a root check begins (not a publish or ready command, a ready or unknown block, a `cd` target that does not exist, no root resolving).
**data** `{ decision: "allow" | "block", reason, command: string | null, roots: string[], receipt: { present, fresh, complete } | null, audit: { present, fresh, blocking } | null }` (the null cases are listed under Transport).

### `rx audit record --preset <file> --entries <file> [--root <dir>] [--json]`  ·  `rx audit show [--root <dir>] [--json]`   (§4.9)

The judgment evidence the receipt cannot hold. **Root** required. **Network** none. **State** writes `repo/audit.json` (`record`), reads it (`show`); reads `repo/receipt.json` for the fingerprint.
`--entries` is one JSON array whose items are rule entries `{ id, scope, result: "pass" | "fail" | "n-a", evidence }` (`id` is a preset rule id or `greptile/<rule id>` for one of the Greptile judgment rules listed in `src/audit/greptile.mjs`, all blocking), dispositions `{ path, localHash, baseline, disposition: "keep-local" | "adopt-published", reason }`, and verifications `{ verification: "writes-files" | "web-requests" | "calls-ai", result, evidence }` (one per external effect the applicability context detects in `src/`). `record` validates: one entry per applicable preset rule (tag ≠ build; `unknown` applicability still requires an entry) and per Greptile judgment rule, else FAIL `audit-coverage`; `severity` comes from the preset, never from the entry: a `block` rule's `fail` → FAIL `audit-<id>`, a `report` rule's `fail` → WARN `audit-<id>`; `rx shortcuts check` and `rx png` (against the receipt's published copy) run in-process and their results are embedded under their own ids, and a shortcut ERROR/FAIL or png FAIL/ERROR is a blocking reason; every stale CHECK/NEW? row in the receipt and every png OLDER-SHOT in this run needs a disposition matching `{ path, localHash, baseline }` exactly, and a disposition matching nothing is also a failure → FAIL `audit-dispositions` (N/A when nothing needs one); a missing or failed verification → FAIL `audit-verification` (N/A when no effect is detected). No current receipt (missing, stale fingerprints, missing step, or written with a different preset) → ERROR `audit-receipt`; a malformed entries file or unknown id → ERROR `input`. The entries file must live outside the extension root; one whose real path is inside it → `ERROR input` (inside, it would enter the payload fingerprint and ship). A duplicate disposition key or verification effect → `ERROR input`. Evidence may span lines (it is recorded in details). `record` deletes the previous `audit.json` before reading its inputs, so a failed recording never leaves an old authorization; an argument error the dispatcher reports before `record` starts (a missing `--entries`, an unknown flag) deletes it too, through the module's `invalidate` export (§1). `audit.json` `{ fingerprint, receiptAt, rxVersion, at, applicable, required: [{ path, localHash, baseline, kind }], effects, entries, dispositions, verifications, evidence: { shortcuts, png }, blocking: string[], reportOnly: string[] }` is written whenever the inputs were valid, blocking reasons included, so `guard` blocks on the latest judgment. `show`: `audit-show` PASS (matches the current receipt, no blocking reason) / WARN (stale, blocking, or no receipt) / `N/A no audit recorded`.
**data** record `{ written, fingerprint, entries, blocking, reportOnly, dispositions, applicable }`; show `{ audit, receipt: { present, fingerprint } }`.

### `rx pr verify <N> --author <login> --extension <name> [--json]`  ·  `rx pr files <N> --extension <name> [--json]`  ·  `rx pr body <N> (--initial <file> | --splice <file>) [--apply] [--prospective <file>] [--repo <owner/repo>] [--json]`   (§4.10)

**Root** none. **Network** GitHub API via `gh` (`--repo` default `raycast/extensions`). **State** `body` keeps a copy of every live body it reads under the cross-repo cache `pr-body/<repo>/<N>/<timestamp>.md` (so a clobbered body is recoverable); `verify` and `files` write nothing.
`verify`: results `pr-author` (login equals `--author`), `pr-head` (head branch is `ext/<name>`), `pr-draft` (is a draft), `pr-open`, `pr-base` (base is `raycast/extensions:main`), each PASS/FAIL.
`files`: `pr-files` PASS when every changed path (rename sources included, all pages fetched) is under `extensions/<name>/`, else FAIL with one detail per stray path.
`body`: the `pr-body.py` safety contract: `--initial` only onto a body that is still the one the PR was created with, and only if it contains Raycast's PR template checklist (`.github/pull_request_template.md` from `raycast/extensions`) verbatim; `--splice` takes `[{ find, replace }]`, each `find` one or more whole lines occurring exactly once, anchors non-overlapping; re-read immediately before the single PATCH; history check after. Without `--apply` → `pr-body-diff` PASS with the diff in details and nothing written to the PR (a backup of the live body is still written to the cache). `--prospective <file>` on a dry run writes the whole composed body (the exact bytes a later `--apply` would send) to that file, so the caller can run `rx scan --pr-text` over it before writing: the diff alone cannot show a value that was already in the live body and has since become forbidden. With `--apply`, `--prospective <file>` binds the write to that scanned file: the body composed now (against the live body re-read in this run) must equal the file byte for byte, else `pr-body-write` FAIL with nothing written (the live body or the edits changed between the scan and the apply; re-run the dry run, scan again, apply again). The file is never rewritten by an `--apply` run. `--apply` without `--prospective` writes unbound and is for bodies the caller scanned directly (`--initial <file>`, where the file IS the body). With `--apply` → `pr-body-write` PASS, WARN when the write verified but GitHub's edit history had not caught up, FAIL when the live body moved (nothing written) or a gap edit was overwritten (the overwritten version in details), or `ERROR pr-body-write` when the write's outcome is unknown. Bodies are exact strings; CRLF survives.
**data** verify: `{ number, author, head, base, draft, state }`; files: `{ files: string[], stray: string[] }`; body: `{ applied, before: "sha256:…", after: "sha256:…", edits: number, overwritten: boolean }`.

### `rx holdout out --preset <file> [--root <dir>] [--json]`  ·  `rx holdout in [--root <dir>] [--json]`   (§4.11)

**Root** required. **Network** none. **State** writes `repo/holdout/inventory.json` and moves files to `repo/holdout/files/`. **Order in a publish:** `out` runs BEFORE `rx gates` and `in` runs after the publication is recorded: held-out entries are part of the payload fingerprint (`src/payload.mjs` skips only `.git`, `.github`, `node_modules`, `raycast-env.d.ts`, `.direnv` and the native build dirs), so a holdout after `gates` stales the receipt and `guard` blocks.
`out` moves **only untracked** entries that the preset's `holdout.localOnly` classifies local-only (default `.env`, `.claude`, `.superpowers`). Never a tracked file; never anything in `ship.keep`. Inventory entries: `{ source, destination, type: "file" | "dir" | "symlink", hash }`. `in` restores each entry, refusing to overwrite a destination that changed, and verifies the hash afterward.
A `ship.keep` entry must carry `extensions` (`ERROR input` otherwise). **Verdicts** `holdout-out` (PASS with one detail per moved path; `N/A nothing untracked matches the preset's localOnly list`), `holdout-tracked` (FAIL if a localOnly path is tracked: it is a committed leak, handle it as a committed deletion; PASS when none is; a tracked path that is also in `ship.keep` is skipped as `keep`, not a FAIL), `holdout-in` (PASS all restored and verified / FAIL destination changed, with the path), `holdout-inventory` (PASS with the entry count; `ERROR` when the inventory is empty while a listed local-only path exists that is neither kept nor tracked, or when it is missing on `in`). `ship.keep` entries apply only when their `extensions` list names this extension's package name; keep protection is ancestor/descendant aware (a kept file inside a local-only directory stays, the rest of the directory moves; a local-only descendant of a kept directory moves). The inventory records the extension root; `in` refuses to restore into a different root. `in` verifies the held copy against the inventory before deleting it as redundant or moving it back; a change on either side keeps both copies and the inventory entry and FAILs `holdout-in` with both paths and hashes. `in` reads no preset.
**data** `{ moved: [...], restored: [...], skipped: [{ path, reason }] }`.

### `rx greptile fetch <N> [--root <dir>] [--json]`  ·  `rx greptile wait <N> [--root <dir>] [--json]`  ·  `rx greptile can-reply <N> [--root <dir>] --round <updated_at> --finding <id> --expected-head <sha> --forbidden <file> --reply <file> --evidence <file> [--claims-fix] [--json]`  ·  `rx greptile drift [--update --dest <dir>] [--json]`   (§4.12)

**Root** `fetch`/`wait`/`can-reply`: optional (the round store lives in the extension's repo state when a root resolves, else in the cross-repo cache under `greptile/<repo>/<N>/`); `drift`: none. **Network** GitHub API via `gh` (all four; `drift` also reads `raycast/extensions` contents). **State** `fetch` writes `rounds/<updated_at>.json` and `seen` (the wait baseline, so the first `wait` after a fetch does not report the fetched round as new); `wait` reads/writes `etag` and `seen`; `can-reply` appends to `replies.json`; `drift --update` writes **only** into `--dest`.
`fetch`: results `greptile-round` PASS with `{ score, updatedAt, reviewedCommit, findings }` in data; no Greptile summary yet → `N/A no Greptile review on #N yet`. Comment lists are paginated to completion (never a silent first page).
`wait`: one ETag-conditional GET. `greptile-wait` PASS `new round <updated_at>` / `N/A no change` (304) / `ERROR greptile-wait` on any failure (never "no change").
`can-reply`: the finding must belong to the stored round; the fetched head must equal `--expected-head`; `--evidence` is JSON `{ finding, disposition: "fixed" | "partial" | "declined", artifact, explanation }`; with `--claims-fix`, `repo/publication.json` (written by the runner's publish step) must name this PR and the current remote SHA, which must differ from the round's reviewed commit; a decline permits an unchanged head. The exact reply bytes are scanned with `--forbidden`. Results `reply-round`, `reply-head`, `reply-evidence`, `reply-publication` (`N/A not a fix claim` without `--claims-fix`), `reply-scan`: each PASS or FAIL; missing, unreadable or mismatched evidence → `ERROR reply-evidence`. Records `{ repo, pr, round, finding, expectedHead, evidenceHash, forbiddenHash, replyHash, at }`.
`drift`: compares `src/rules/greptile/` (the core snapshot, versioned with the package; `SOURCE.json` records repo, source (`main` or a PR), SHA, fetch date) with the live `.greptile/` in `raycast/extensions`. `greptile-drift` PASS no drift / FAIL with one detail per change (`rule added`, `rule removed`, `rule changed <id> <field>`, `files changed`, `rules.md changed`, `source moved`) / `ERROR greptile-drift` when the live copy cannot be read. `--update` requires `--dest <maintainer checkout>` and rewrites that checkout's `src/rules/greptile/` from the live copy; a `--dest` whose real path is the running package's own snapshot directory is refused (`ERROR greptile-drift`). `source moved` is one of `data.changes`.
**data** fetch `{ repo, pr, head, round: { score, updatedAt, reviewedCommit, summary (the summary comment's body, where a summary-only finding lives), findings: [{ id, path, line, originalCommitId, body }] } }`; wait `{ etag, changed, updatedAt }`; can-reply `{ authorized: boolean, record }`; drift `{ snapshot: SOURCE.json, live: { source, sha }, changes: string[] }`.

Two subcommands (the plan writes them as `--runtime`/`--check`; they are subcommands so each has its own root rule). **Root** `runtime`: none; `check`: required. **Network** none. **State** `runtime` writes `cache/shortcuts/<shimFingerprint>.json` `{ appVersion, shimFingerprint, shortcuts: { [name]: { modifiers, key } } }` from the installed Raycast app's API shim; `check` reads the table matching the running app (or `--table`).
`check` compares the extension's resolved action panels (every `shortcut` literal, `Keyboard.Shortcut.Common.*` reference and object-literal shortcut such as a toast `primaryAction`) with the table. Results `shortcut-runtime-table` (PASS table found / `ERROR runtime evidence unavailable` when the extension declares any shortcut and no matching table exists, or the cached table's `shimFingerprint` differs from the installed shim / `N/A extension declares no shortcuts`), `shortcut-ambiguous` (FAIL per conflicting pair **on a declared platform**, details with both sites as file:line; two sites on opposite sides of one `cond ? (…) : (…)` are not a pair **only when the ternary is evaluated once per panel**; inside a repeated render such as `items.map(…)` both branches can render into the same panel and the pair stands). The envelope `fingerprint` stays `null` for both subcommands (the shim fingerprint is data). `runtime` looks for Raycast.app in `/Applications` and `~/Applications` and accepts `--app <path>` as an explicit override. **data** runtime `{ appVersion, shimFingerprint, path, count }`; check `{ table: { path, appVersion, shimFingerprint } | null, declared, conflicts: [{ platforms, binding, sites: [{ file, line, title, source }] }], reserved: [{ platforms, binding, why, site }], platforms, unresolved: [{ file, line, title, source }], groups: { panels, toasts, loose }, files }`.

### `rx preset check <file> [--json]`  ·  `rx preset table <file> --into <reference.md> [--check] [--json]`   (§4.16)

**Root** none. **Network** none. **State** `table` rewrites the region between `<!-- rx:matrix:start -->` and `<!-- rx:matrix:end -->` in `--into` (or only compares with `--check`).
`check`: `preset-schema` (valid against `schema/preset.schema.json`, unknown fields rejected), `preset-ids` (no duplicate ids), `preset-anchors` (every `anchor` resolves to a heading in its reference file, resolved relative to the preset file), `preset-bindings` (a non-build rule has ≥ 1 binding; each `rx` binding names a check in `rx commands --json`, each `eslint` binding a rule in `eslint-plugin/`, each `judgment` binding a decision in `src/judge/decisions/` or the preset's `judgments[]`), `preset-severity` (no `report` rule binds a core check that can FAIL; capability comes from the registry's `levels` for the bound check, from the preflight catalog for preflight checks, and otherwise the check is assumed able to FAIL, so the binding fails with a message naming the `levels` declaration that would allow it). ### `rx judge ask <decision-id> --inputs <file> [--provider jev|haiku|agent] [--json]`  ·  `rx judge eval <decision-id> [--provider …] [--json]`   (§4, D6, Phase 7)

Advisory only; never blocks, never acts. **Root** none. **Network** the chosen provider's API only: Jev `POST https://api.typesafe.ai/v1/systemone` (`TYPESAFE_API_KEY`), Claude Haiku `POST https://api.anthropic.com/v1/messages` (`ANTHROPIC_API_KEY`), 30 s timeout; `agent` mode: none. **State** none.
**Decisions** live in `src/judge/decisions/<id>.json` `{ id, question, answers[], inputs (JSON Schema), fixtures: [{ inputs, expected, source }] }`; `source` is the receipt the fixture came from, a `~/…:<line>[-<line>]` path, or `synthetic: <why>` when no real receipt exists for that answer. A decision file is validated on load (shape, id equals file name, every fixture's `expected` is one of `answers` and its `inputs` pass the inputs schema); an unknown or malformed decision → `ERROR input`. Shipped: `changelog-user-visible` (`user-visible` / `internal` / `branch-only-bug`), `review-finding-triage` (`valid` / `valid-wrong-remedy` / `false-positive` / `conflicts-with-chris`), `needs-code` (`code` / `metadata-only`), `png-provenance` (`ours-newer` / `contributor` / `unclear`).
**Provider choice.** `--provider` wins (anything but `jev`, `haiku`, `agent` → `ERROR args`). Without it (D6): `jev` when `TYPESAFE_API_KEY` is set, else `haiku` when `ANTHROPIC_API_KEY` is set, else `agent`. Jev is implemented against its public API reference (`https://docs.typesafe.ai/api`, fetched 2026-11-04): one `choice` question whose criteria are the decision's answers, `probabilities` read from the answer (`probabilitySource: "provider-reported"`). Haiku (`claude-haiku-5-5`, `anthropic-version: 2026-10-21`, plain `fetch`) gets no token probabilities from the Messages API, so the request forces one call of a tool whose input is a probability per answer (`probabilitySource: "model-reported"`). Either way the values are normalized to sum to 1, and **nothing calls them calibrated**.
**ask.** `judge-inputs` PASS when `--inputs` is valid against the decision's `inputs` schema (the validator in `src/preset/schema.mjs`); unreadable JSON or a schema error → `ERROR judge-inputs` with one detail per error, and no provider is called. Provider mode: `judge-<id>` PASS with `data.answer` when the top probability is ≥ 0.7, WARN `defer-to-agent` below (with `data.prompt`). **Provider error** (missing key, HTTP error, timeout, refusal, malformed output: a missing answer, an unknown key, a non-number or out-of-range value, a sum of 0, no tool call / no choice answer; for Haiku also `stop_reason: "max_tokens"`, and an invalid tool block under any `stop_reason` other than `tool_use`) → WARN `judge-provider` naming it, then agent mode in the same run. Provider text can hold newlines; the WARN message carries its first line and each further line is a detail. Agent mode: `judge-<id>` `N/A agent mode: decide and record in the audit` with `data.prompt` `{ question, answers, inputs }`; no probabilities, no accuracy claim. In text output the agent-mode N/A (after a fallback too) and the `defer-to-agent` WARN carry the prompt as three details: `question: …`, `answers: …`, `inputs: <compact JSON>`.
**eval.** One `judge-eval` per fixture in provider mode: PASS when the answer clears 0.7 and equals `expected`, FAIL otherwise (a deferral is a FAIL: the provider did not produce the answer); `judge-accuracy` PASS when every fixture is right (the v0.1 adoption rule for showing a provider suggestion) and WARN otherwise, with `data.accuracy` = correct / total. Agent mode: each fixture `N/A agent mode makes no prediction`, `judge-accuracy` N/A, `data.accuracy` null. A provider error on any fixture → WARN `judge-provider` and the whole run in agent mode (no partial accuracy).
**Why this never blocks.** `ask` can only emit PASS/WARN/N/A for the judgment, so it exits 0 whatever a provider answers or fails to answer; its only non-zero exit is `ERROR` (2) for a malformed call, which the caller must fix and is not a judgment. `eval` exits 1 when a fixture FAILs: a measurement of the provider for the adoption rule, not a gate. No `judge` result is a step in `rx gates`' receipt or an entry `rx audit` requires, and `rx guard` reads neither, so no judge exit code or verdict can stand between an agent and a publish. Registry `levels`: `judge-*` (ask) `PASS WARN N/A`, `judge-provider` `WARN`, `judge-inputs` `PASS ERROR`, `judge-eval` `PASS FAIL N/A`, `judge-accuracy` `PASS WARN N/A`.
**data** ask `{ decision, mode: "provider" | "agent", provider, answer: string | null, top: { answer, probability } | null, probabilities: Record<answer, number> | null, probabilitySource: "provider-reported" | "model-reported" | null, latencyMs: number | null, threshold: 0.7, fallback: { provider, error } | null, prompt?: { question, answers, inputs } }`; eval `{ decision, mode, provider, probabilitySource, accuracy: number | null, correct: number | null, total, fallback, cases: [{ index, source, expected, answer, top, probabilities, latencyMs, verdict }] }`.

### `rx api-diff <from> <to> [--out <dir>] [--json]`   (§4.14, Phase 8)

The deterministic half of the api-changelog skill: what moved between two published versions of `@raycast/api`, read from the npm tarballs. It fixes Q15–Q17 and Q22 by construction. **Root** none. **Network** required: `npm view @raycast/api time --json`, then `npm pack @raycast/api@<v> --pack-destination <tmp>` for `<from>` and `<to>`. **State** none.

**Arguments.** `<from>` and `<to>` are exact published versions (`2.10.1`, not a range, a tag or `latest`). A version that is not exact, or not in npm's `time` map → `ERROR args`. They may be given in either order; the earlier-published one is the baseline. When either endpoint's `time` value equals another version's, the publish order is ambiguous → `ERROR api-diff` naming the tie. Two equal versions → `ERROR args`. `--out <dir>` extracts both packages to `<dir>/<version>/package/` and leaves them for the skill's bundle mining. `data.dirs` holds those two absolute `package/` paths. On an ERROR, the run removes the `<dir>/<version>/` directories it created, so a retry is not refused. Without it, a temp dir is used and removed on every exit path. Each `<dir>/<version>/` is reserved with a non-recursive `mkdir` before any npm call. If it already exists (a directory, a file or a dangling symlink), the result is `ERROR args`: never overwrite. Cleanup on an ERROR removes only the directories this run reserved.

**Checks.**
- `api-diff-window`: PASS when `<from>` and `<to>` are adjacent in publish order. WARN `N intermediate version(s): …` when others were published between them. Changes may belong to any of them, so the skill diffs adjacent pairs before attributing a change. The list is in `data.window`.
- `api-diff`: PASS with a one-line summary (`A added, R removed, C changed; types/index.d.ts +x −y`). The details hold each added, removed and changed path (`+ path`, `- path`, `~ path fromBytes→toBytes`), then the unified diff of `types/index.d.ts`. Rule: N/A `only version fields changed` when no file was added or removed and every changed file is `versionOnly`. A changed file is `versionOnly` only by one of two narrow rules. For a `.json` file, both sides parse, and setting the baseline's top-level `version` to `<to>` gives a deep-equal value (key order ignored). For any other file, it is text (no NUL byte) and holds the `<from>` string exactly once, and that occurrence is a whole quoted literal (`"<from>"` or `'<from>'`, the quote on both sides). Replacing it with the same literal for `<to>` must give the new content byte for byte. A substring such as `2.1.1` inside `2.1.10`, `^2.1.1` or `2.1.1/model` never qualifies. A file whose mode or kind changed is never `versionOnly`. Anything else is a real change, including a dependency range or a URL that also moved. Equal sizes and digit-only byte differences prove nothing (Q17). A pack, extraction or read failure for either version (including a missing `package/`, a missing `types/index.d.ts`, a malformed `oclif.manifest.json`, or any symlink or non-regular file in an extracted package: npm packs neither, and a link could pull a host file into the diff) → `ERROR api-diff` naming the version (never an empty diff; Q16).

**data** `{ package: "@raycast/api", from, to, published: { from, to }, window: string[] (strictly between, publish order), dirs: { from, to } | null (only with --out), files: { added: string[], removed: string[], changed: [{ path, fromBytes, toBytes, fromMode, toMode, versionOnly: boolean }] }, versionOnly: boolean, declarations: { path: "types/index.d.ts", changed: boolean, added: number, removed: number, diff: string }, distTypes: { added: string[], removed: string[], changed: string[] }, cli: { commandsAdded: string[], commandsRemoved: string[], flagsAdded: [{ command, flag }], flagsRemoved: [{ command, flag }], changed: [{ path, kind: "added" | "removed" | "changed", from?, to? }] } }`. Paths are relative to `package/`, sorted. `cli` compares `oclif.manifest.json` `commands` and their `flags` on both sides; `cli.changed` lists every other leaf under `commands` whose value differs (a flag's `default`, `options`, `required`, `char`, a description, args), with `path` a dotted path such as `commands.lint.flags.fix.default` and `from`/`to` the JSON values, sorted by path. A leaf present on one side only has `kind` `added` or `removed` and omits the missing side, so an explicit JSON `null` stays distinguishable from absence. Arrays are leaves. Leaves of an added or removed command or flag are not repeated in `changed`, and `flagsAdded`/`flagsRemoved` cover only commands present on both sides (a missing manifest on either side → empty lists plus a detail line saying so). `diff` is unified with three lines of context and labels `a/types/index.d.ts` / `b/types/index.d.ts`, or `""` when unchanged.

Exit: 0 (PASS/WARN/N/A), 2 (ERROR). Nothing here can FAIL: the command describes a release; it does not judge one.
